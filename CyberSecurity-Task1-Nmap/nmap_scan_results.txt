========================================================
PORT-BY-PORT SECURITY ANALYSIS
========================================================

### Port 21 - FTP (vsftpd 2.3.4)
What it does: Transfers files between client and server.
Security Risk: CRITICAL. This exact version (vsftpd 2.3.4) contains a
known backdoor vulnerability (CVE-2011-2523) that was maliciously
inserted into the source code and allows unauthenticated remote root
access. This is one of the most well-known intentionally vulnerable
services used for training.
Recommendation: Upgrade immediately, or disable FTP and use SFTP/FTPS.

### Port 22 - SSH (OpenSSH 4.7p1)
What it does: Provides encrypted remote login and administration.
Security Risk: HIGH (for this version). OpenSSH 4.7p1 is very outdated
and affected by multiple known vulnerabilities. While SSH is
encrypted by design, old versions lack modern protections and may be
vulnerable to user enumeration and other attacks.
Recommendation: Upgrade to the latest OpenSSH, use key-based
authentication, disable root login, disable password authentication.

### Port 23 - Telnet (Linux telnetd)
What it does: Provides remote command-line login.
Security Risk: CRITICAL. Telnet transmits all data, including
usernames and passwords, in plaintext. Anyone sniffing the network
can capture credentials.
Recommendation: Disable Telnet entirely; use SSH instead.

### Port 25 - SMTP (Postfix)
What it does: Sends and relays email.
Security Risk: MEDIUM. Can be abused as an open mail relay for spam,
or used to enumerate valid usernames (VRFY command) if misconfigured.
Recommendation: Restrict relay to authenticated/internal users only,
disable VRFY/EXPN.

### Port 53 - DNS (ISC BIND 9.4.2)
What it does: Resolves domain names to IP addresses.
Security Risk: HIGH (for this version). This BIND version is old and
has known vulnerabilities including cache poisoning and denial-of-
service issues.
Recommendation: Upgrade to a current, patched BIND version; restrict
zone transfers and recursive queries to trusted hosts.

### Port 80 - HTTP (Apache 2.2.8, Ubuntu, DAV/2)
What it does: Serves web content over unencrypted HTTP.
Security Risk: HIGH. This is an old, unsupported Apache version with
multiple known CVEs. WebDAV (DAV/2) being enabled adds additional
attack surface (e.g., file upload/manipulation if misconfigured).
Recommendation: Upgrade Apache, disable WebDAV if unused, migrate to
HTTPS.

### Port 111 - RPCbind
What it does: Maps RPC program numbers to network port numbers,
used to coordinate services like NFS.
Security Risk: HIGH. RPCbind is frequently used for reconnaissance
and has historically been abused in DDoS amplification attacks and
to enumerate other vulnerable RPC services running on the host.
Recommendation: Disable or firewall if RPC services are not required
externally.

### Port 139 & 445 - NetBIOS/SMB (Samba 3.X - 4.X)
What it does: Provides Windows-style file/printer sharing.
Security Risk: CRITICAL. This version range of Samba includes builds
vulnerable to remote code execution (e.g., the "usermap script"
vulnerability, CVE-2007-2447). SMB has historically been one of the
most exploited services (e.g., EternalBlue/WannaCry).
Recommendation: Upgrade Samba immediately, restrict SMB access to
trusted internal networks only, disable if not needed.

### Port 512 - Exec (rexecd)
What it does: Allows remote command execution (legacy "r-services").
Security Risk: CRITICAL. rexec sends credentials in plaintext and
has no meaningful authentication protections by modern standards.
Recommendation: Disable entirely; replace with SSH-based remote
execution.

### Port 513 - Login (rlogin)
What it does: Legacy remote login service.
Security Risk: CRITICAL. Like rexec, rlogin transmits data
unencrypted and can allow trust-based logins without a password
(.rhosts files), enabling easy unauthorized access.
Recommendation: Disable entirely; replace with SSH.

### Port 514 - Shell (tcpwrapped)
What it does: Part of the legacy "r-services" suite (rsh), used for
remote command execution.
Security Risk: CRITICAL. Same risk profile as rexec/rlogin —
unencrypted, weak/trust-based authentication.
Recommendation: Disable entirely.

### Port 1099 - Java-RMI (GNU Classpath grmiregistry)
What it does: Java Remote Method Invocation registry, used for
distributed Java applications.
Security Risk: HIGH. RMI registries are commonly exploited for
remote code execution if they allow untrusted deserialization or
lack authentication.
Recommendation: Disable if unused; restrict access; keep Java/RMI
libraries patched.

### Port 1524 - Bindshell (Metasploitable root shell)
What it does: In this lab image, this is a pre-planted backdoor that
provides an immediate root shell with no authentication.
Security Risk: CRITICAL. This is an intentional backdoor left open
for training purposes — in a real environment, any unauthenticated
shell access is a total compromise of the system.
Recommendation: This should never exist on a real system; if found,
treat it as an active compromise and investigate immediately.

### Port 2049 - NFS
What it does: Network File System, allows remote file system
mounting/sharing.
Security Risk: HIGH. Misconfigured NFS exports can allow unauthorized
users to read/write sensitive files, especially if exported with weak
or no access restrictions.
Recommendation: Restrict NFS exports to specific trusted hosts, avoid
exporting with root/no_root_squash permissions.

### Port 2121 - FTP (ProFTPD 1.3.1)
What it does: A second FTP server running on a non-standard port.
Security Risk: CRITICAL. ProFTPD 1.3.1 has known remote code
execution vulnerabilities from that era.
Recommendation: Upgrade or remove; do not run duplicate/unnecessary
FTP services.

### Port 3306 - MySQL (5.0.51a-3ubuntu5)
What it does: Relational database service.
Security Risk: HIGH. This MySQL version is very outdated with known
vulnerabilities, and having a database port exposed to the network
(rather than bound to localhost) significantly increases risk of
unauthorized data access.
Recommendation: Bind MySQL to localhost unless remote access is
required, use strong authentication, restrict via firewall, upgrade
version.

### Port 5432 - PostgreSQL (8.3.0 - 8.3.7)
What it does: Relational database service.
Security Risk: HIGH. Outdated PostgreSQL version with known
vulnerabilities; direct external database exposure is risky.
Recommendation: Bind to localhost/internal network only, enforce
strong authentication (pg_hba.conf), upgrade version.

### Port 5900 - VNC (protocol 3.3)
What it does: Provides remote desktop/screen-sharing access.
Security Risk: CRITICAL. VNC protocol 3.3 is very old and has weak
authentication; some configurations allow connection with no
password at all, giving full remote desktop control.
Recommendation: Disable if unused, require strong authentication,
tunnel over SSH/VPN, never expose directly to the internet.

### Port 6000 - X11
What it does: X Window System, used for GUI display forwarding.
Security Risk: HIGH. X11 servers exposed to the network can allow
attackers to capture keystrokes, take screenshots, or inject input
if access control is not properly configured (access was denied in
this scan, which is good, but the port itself being open is still
worth reviewing).
Recommendation: Restrict X11 to localhost/SSH tunneling only; do not
expose directly.

### Port 6667 - IRC (UnrealIRCd)
What it does: Internet Relay Chat server.
Security Risk: CRITICAL. This specific UnrealIRCd version is
historically associated with a well-known trojanized backdoor
(CVE-2010-2075) that allowed unauthenticated remote command
execution.
Recommendation: Remove/disable if not a legitimate business need;
upgrade immediately if IRC service is required.

### Port 8009 - AJP13 (Apache JServ Protocol)
What it does: Connector protocol between Apache HTTP Server and
Tomcat.
Security Risk: HIGH. AJP has known vulnerabilities (e.g., the
"Ghostcat" file read/inclusion vulnerability, CVE-2020-1938) when
exposed without restriction.
Recommendation: Bind AJP connector to localhost only, or disable if
not required; upgrade Tomcat/Apache.

### Port 8180 - HTTP (Apache Tomcat/Coyote 1.1)
What it does: Serves Java web applications (Tomcat's own HTTP
connector, running on a secondary port).
Security Risk: HIGH. Old Tomcat/Coyote versions have known
vulnerabilities, and default/weak Tomcat manager credentials are a
common attack vector for full server compromise.
Recommendation: Upgrade Tomcat, remove/secure the default manager
application, change default credentials, restrict access.


========================================================
OVERALL SECURITY ASSESSMENT
========================================================

This target (192.168.179.155) is running the Metasploitable2
intentionally vulnerable Linux image, used for security training and
practice. It exposes 23 open ports, running severely outdated
versions of common services (FTP, SSH, SMB, databases, web servers),
several of which contain publicly known, critical vulnerabilities
including:
  - vsftpd 2.3.4 backdoor (CVE-2011-2523)
  - UnrealIRCd backdoor (CVE-2010-2075)
  - Samba usermap script RCE (CVE-2007-2447)
  - A pre-planted root bindshell on port 1524

In a real production environment, a host in this state would
represent an almost total compromise risk — multiple independent
paths to unauthenticated remote root access exist. Key
recommendations for any real system showing similar results:
  1. Immediately patch or remove all outdated/vulnerable services.
  2. Disable all legacy, unencrypted protocols (Telnet, rexec,
     rlogin, rsh).
  3. Restrict database and file-sharing services (MySQL, PostgreSQL,
     NFS, SMB) to internal/trusted networks only.
  4. Remove unnecessary services entirely to reduce attack surface.
  5. Apply the principle of least privilege and network segmentation.

Note: This scan was performed against an isolated local lab VM,
specifically designed to be vulnerable for educational purposes, with
full authorization as the VM owner. No external or production
systems were scanned.
