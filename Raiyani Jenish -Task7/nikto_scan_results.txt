DETAILED FINDINGS - WHAT / WHY / FIX

--------------------------------------------------------
[HIGH] Finding: Exposed .git Repository
(/dvwa/.git/index, /dvwa/.git/HEAD, /dvwa/.git/config)
--------------------------------------------------------
What it is: The application's .git folder (its version control
history) is publicly accessible via the web server.

Why it is a risk: An exposed .git directory can allow an attacker
to reconstruct the entire source code, including historical
commits that may contain hardcoded credentials, API keys,
database connection strings, or old vulnerable code paths. Tools
like "git-dumper" can automatically download an entire repository
from an exposed .git folder. This is one of the most damaging
misconfigurations Nikto can find, as it can lead to full source
code and secrets disclosure.

How to fix it:
  - Remove the .git directory from the web-accessible document
    root entirely, or move the deployed code outside of version
    control before publishing.
  - Add a web server rule to deny access to any ".git" path
    (e.g., in Apache: "RedirectMatch 404 /\.git").
  - Rotate any credentials/secrets that may have ever existed in
    the repository's history.

--------------------------------------------------------
[HIGH] Finding: Directory Indexing Enabled - /dvwa/config/
--------------------------------------------------------
What it is: Browsing to /dvwa/config/ without a specific file
returns a full listing of the directory's contents instead of a
403/404 error.

Why it is a risk: This directory typically holds the application's
configuration file (config.inc.php), which may contain database
credentials, secret keys, or other sensitive settings. Directory
listing makes it trivial for an attacker to discover and download
these files.

How to fix it:
  - Disable directory indexing for this path
    ("Options -Indexes" in Apache).
  - Explicitly deny direct web access to the /config/ folder,
    or move sensitive config files outside the public web root.
  - Ensure config files are not readable via direct URL request
    regardless of indexing (e.g., block .php config files from
    direct execution/download where not needed).

--------------------------------------------------------
[MEDIUM] Finding: Configuration Information May Be Available Remotely
--------------------------------------------------------
What it is: Nikto flags that configuration-related information
tied to /dvwa/config/ may be retrievable over the network.

Why it is a risk: Exposed configuration details (database names,
internal paths, credentials) give an attacker a head start on
further attacks, such as direct database access or targeted
exploitation of known application internals.

How to fix it:
  - Restrict access to configuration files at the web server
    level (deny direct HTTP access to *.inc.php / config files).
  - Store secrets in environment variables or a secrets manager
    instead of a web-accessible config file where possible.

--------------------------------------------------------
[MEDIUM] Finding: Missing Content-Security-Policy (CSP) Header
--------------------------------------------------------
What it is: The server does not send a Content-Security-Policy
header in its HTTP responses.

Why it is a risk: CSP is one of the strongest browser-side
defenses against Cross-Site Scripting (XSS) and data-injection
attacks, since it restricts which scripts/resources a page is
allowed to load or execute. Without it, a successful XSS
vulnerability elsewhere in the app has a much larger impact.

How to fix it:
  - Add a Content-Security-Policy header appropriate to the
    application (e.g., "default-src 'self'"), then refine it
    based on what resources the app legitimately needs to load.

--------------------------------------------------------
[MEDIUM] Finding: Missing Strict-Transport-Security (HSTS) Header
--------------------------------------------------------
What it is: The server does not send a Strict-Transport-Security
header.

Why it is a risk: Without HSTS, browsers will not automatically
force HTTPS on future visits, leaving a window for downgrade or
man-in-the-middle attacks that intercept the initial unencrypted
request (relevant once/if this site is served over HTTPS).

How to fix it:
  - Serve the site over HTTPS and add:
    "Strict-Transport-Security: max-age=31536000; includeSubDomains"

--------------------------------------------------------
[LOW] Finding: Missing X-Content-Type-Options Header
--------------------------------------------------------
What it is: The server does not send
"X-Content-Type-Options: nosniff".

Why it is a risk: Without this header, some browsers may
"MIME-sniff" a response into a different content type than
declared, which can be abused in certain XSS attack scenarios.

How to fix it:
  - Add "X-Content-Type-Options: nosniff" to the server's default
    response headers.

--------------------------------------------------------
[LOW] Finding: Missing Referrer-Policy Header
--------------------------------------------------------
What it is: The server does not send a Referrer-Policy header.

Why it is a risk: Without a defined policy, the browser's default
behavior may leak the full referring URL (which can include
sensitive query parameters or internal paths) to third-party sites
when a user clicks an outbound link.

How to fix it:
  - Add "Referrer-Policy: strict-origin-when-cross-origin" (or a
    stricter policy) to the server's response headers.

--------------------------------------------------------
[LOW] Finding: Missing Permissions-Policy Header
--------------------------------------------------------
What it is: The server does not send a Permissions-Policy header.

Why it is a risk: Without this header, the site does not
explicitly restrict which browser features (camera, microphone,
geolocation, etc.) pages can request, which is a defense-in-depth
gap rather than a direct exploit path.

How to fix it:
  - Add a Permissions-Policy header disabling unused browser
    features, e.g.:
    "Permissions-Policy: geolocation=(), camera=(), microphone=()"

--------------------------------------------------------

What it is: Nikto identified a discoverable admin/login page at a
